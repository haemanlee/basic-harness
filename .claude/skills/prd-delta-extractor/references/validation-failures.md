# validate_spec.py 실패 시 대응

`validate_spec.py`가 0이 아닌 코드로 종료했을 때만 이 문서를 연다.

## 흔한 실패 패턴과 대응

| 실패 메시지 | 원인 | 대응 |
|---|---|---|
| `missing required field 'X'` | 슬라이드에 해당 정보가 없거나 추출 시 누락 | 슬라이드를 다시 확인해 있으면 채우고, 정말 없으면 지어내지 말고 사용자에게 해당 `REQ-####`와 필드명을 짚어 질문한다 |
| `duplicate id` | 같은 슬라이드/버전에서 REQ ID를 잘못 재사용 | 두 요구사항이 실제로 같은 것인지 확인 — 같으면 병합, 다르면 하나에 새 ID를 부여한다 |
| `id must look like REQ-####` | ID 포맷 오류 | `REQ-` + 4자리 숫자로 정정한다 |
| `done_when item too vague` (8자 미만) | 완료 조건이 검증 불가능한 표현 | "빠름", "잘 됨" 같은 표현 대신 관찰 가능한 조건(상태 코드, 로그, DB 상태)으로 재작성한다 |

## 원칙

실패를 조용히 무시하고 `spec.yaml`을 그대로 커밋 대상으로 안내하지 않는다. 재검증까지 통과한 뒤에만 다음 단계(diff/AC)로 넘어간다.
